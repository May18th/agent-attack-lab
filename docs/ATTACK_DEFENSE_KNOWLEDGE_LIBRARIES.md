# 攻防实验室知识库与人工初始化清单

## 1. 目的

本文档定义智能体攻防实验室中 Attacker、Defender 和 Arbiter 所需的知识库、初始化方式、学习更新流程和访问边界。目标是确保：

- Attacker 能在授权范围内选择样本、生成意图与策略并根据公开结果复盘；
- Defender 能按 L0 -> L1 -> L2 -> L3 执行检测、阻断、控制和恢复；
- Arbiter 能依据隐藏真值、安全对照和完整证据独立裁决；
- 自动学习不会泄露隐藏规则，也不会把误判直接写入正式规则库；
- 所有库均可追溯、可版本化、可审核和可回滚。

评分与流程以 `攻防评分细则_修订版_v2.0.md` 为准。

## 2. 流程映射说明

需要特别区分以下环节：

| 环节 | 角色 | 使用的数据 |
|---|---|---|
| A1 读取战局配置 | Attacker | 主题、难度、授权范围、公开反馈和规则版本 |
| A2 选择样本与攻击面 | Attacker | 合法样本库、允许的攻击面 |
| A3 选择意图和策略 | Attacker | 难度、攻击面、策略种子、历史公开结果 |
| A4 构建合成 Payload | Attacker | A2/A3 结果、Payload 模板与格式规范 |
| A8 结果接收与复盘 | Attacker | Arbiter 已公开的裁决和证据 |
| L0-2 基础规则检查 | Defender | 黑名单、注入模板和高危模式库 |
| L2 工具动作管控 | Defender | 工具白名单、参数策略、权限和时序规则 |
| L3 审计与恢复 | Defender | 审计策略、隔离、回滚和恢复策略 |

因此，主题黑名单属于 Defender 的 L0-2，不属于 Attacker 的 A1。

## 3. 必须人工初始化的库

### 3.1 主题与场景配置库

每个主题至少包含：

- `themeId`、名称、业务背景和风险类型；
- 允许攻击的模拟目标和攻击面；
- 禁止访问的真实资源；
- 低、中、高难度要求；
- 建议回合数；
- 允许使用的模拟工具；
- 预期风险和授权边界；
- 版本、创建人、审核人和状态。

该库是 A1 配置的主要来源。

### 3.2 Attacker 样本库

由人工为每个主题准备合法、合成且可复现的初始样本。每条样本至少包含：

- `sampleId`、主题、难度和样本类型；
- 攻击面、建议目标层和风险类别；
- 可供 Attacker 理解的意向提示；
- 合成输入、格式、变量和预期模拟效果；
- 授权范围、来源、版本和审核状态。

不同难度应体现策略复杂度和目标层差异，而不是简单修改文字长度。样本不得包含真实凭据、真实目标或生产数据。

### 3.3 Attacker 初始意图与策略种子库

该库为 A3 提供人工初始化能力，随后由 Attacker 通过 A8 公开结果逐步形成自己的意图策略库。初始记录至少包括：

- 适用主题、难度和攻击面；
- 模拟攻击意图；
- 策略描述和变化方法；
- 适用前提、禁止行为和失败条件；
- 预期目标层；
- 版本和审核状态。

Attacker 自动学习时只能使用公开裁决，不得读取 Defender 黑名单、隐藏真值或安全对照样本。

### 3.4 授权范围与攻击面库

人工定义每个主题允许和禁止的行为：

- 允许测试的模型、工具和模拟资源；
- 允许的攻击面和模拟效果；
- 禁止使用的真实地址、凭据、文件和外部目标；
- Payload 长度、编码、结构和必填字段；
- 越界和违规判定条件。

该库供 A1、A2、A5 和 Arbiter 使用。

### 3.5 Payload 模板与格式规范库

每种样本类型应有人工审核的合成 Payload 模板：

- Payload 类型和字段结构；
- 必填字段和变量约束；
- 预期模拟效果；
- 禁止字段和敏感数据占位规则；
- 编码、长度和解析规则；
- 模板版本和哈希。

Attacker 可以在模板基础上生成变体，但必须经过 A5 授权和格式自检。

### 3.6 Defender 黑名单与基础规则库

人工按“全局基础规则 + 主题覆盖规则”的方式初始化，避免每个主题重复维护全部规则。至少包含：

- `ruleId`、主题、模式类型和严重等级；
- 黑名单词、注入模板或结构特征；
- 匹配方式、适用范围和例外条件；
- 命中后的动作；
- 规则版本、来源和审核状态；
- 假阳性测试结果。

该库对应 L0-2。命中规则不等于正确拦截，最终仍须由 Arbiter 根据隐藏真值确认。

### 3.7 Defender 输入边界规则库

用于 L0-1 和 L0-3，人工定义：

- 编码、换行、空白和转义标准化规则；
- 最大长度、最大嵌套深度和允许结构；
- 禁止字段、异常边界和授权范围；
- 解析失败和畸形输入处置方式；
- 原文快照与标准化快照的保留要求。

### 3.8 Defender 工具白名单与权限策略库

用于 L2，至少包含：

- 允许的工具、动作和模拟目标资源；
- 参数规范化和危险参数规则；
- 主体、角色、作用域和资源权限；
- 调用频率、批量、顺序、幂等和重放策略；
- 沙箱执行条件和结果验证方式；
- 策略版本和审核状态。

前端隐藏按钮不能代替后端权限校验。

### 3.9 安全对照样本库

每个有效攻击回合应绑定一个独立安全对照样本，用于验证 Defender 是否误拦截。每条记录至少包括：

- `controlSampleId` 和适用主题；
- 正常业务输入和合法工具动作；
- 预期结果 `safe-pass`；
- 预期输出和通过条件；
- 难度、版本和隐藏标签。

安全对照样本只允许 Arbiter 调用，不得提供给 Attacker。

### 3.10 Arbiter 隐藏真值与裁决库

该库是可信评分的核心，由人工建立并与 Attacker、Defender 隔离。至少包含：

- `testCaseId` 和关联样本；
- 攻击样本有效性；
- 各层预期结果和穿透证据要求；
- 有效阻断条件；
- L2 模拟效果判定；
- L3 控制窗口和成功条件；
- 正确最终分类；
- 安全对照正确结果；
- 评分证据要求和裁决版本。

双方只能看到 Arbiter 明确公开的裁决结果，不能读取完整隐藏真值。

### 3.11 隔离、回滚与恢复策略库

用于 L3-3，人工定义：

- 隔离、撤销和回滚动作；
- 控制时间窗口；
- 恢复后的正确状态；
- 验证步骤、通过条件和失败条件；
- 不可恢复时的处置方式；
- 策略版本和审计要求。

### 3.12 评分规则与响应阈值库

评分规则不得只写死在前端。人工维护并版本化：

- A-01 至 A-06、D-01 至 D-07 的分值和证据要求；
- 基础攻防 95%、响应 5% 的权重；
- Attacker 和 Defender 响应时间分档；
- 相似度阈值；
- 无效回合、违规和 `system-void` 规则；
- 整局平均、同分比较和 N/A 规则。

每局开始时锁定规则版本，中途修改必须生成新版本战局。

## 4. 系统学习产生、但必须审核后生效的库

### 4.1 Attacker 回合策略记忆库

由 A8 根据公开信息自动更新，建议字段包括：

- 战局、回合、主题和难度；
- 样本、攻击面、意图、策略和变化原因；
- 最深穿透层、公开拦截原因和得分；
- 下一回合策略；
- 来源战局、创建时间和记忆版本。

该库不得保存或推断隐藏规则。

### 4.2 Defender 候选特征库

Defender 学习产生的新特征先进入候选区，不能直接进入正式规则库。每条候选特征至少包含：

- 特征 ID、来源主题、样本和证据；
- 特征表达、适用范围和建议动作；
- 相似度、置信度和模型版本；
- 安全对照和反例测试结果；
- 假阳性率；
- `pending`、`approved`、`rejected`、`revoked` 状态；
- 提出人、审核人和生效时间。

推荐发布流程：

```text
发现候选特征
  -> 写入隔离候选区
  -> 安全样本和反例回归
  -> Arbiter 核验证据
  -> 人工审核
  -> 发布新规则版本
  -> 正式特征库生效
```

### 4.3 修复建议知识库

Defender 可根据历史结果生成修复建议，但正式复用前应审核：

- `action`；
- `verificationSteps`；
- `passCriteria`；
- `failCriteria`；
- 关联证据、适用主题和版本。

### 4.4 相似样本索引库

系统根据已审核样本自动生成向量或其他相似度索引，保存：

- 样本 ID、模型版本和向量版本；
- 与历史样本的最大相似度；
- 最近样本 ID；
- `baseline`、`same-source`、`new-source` 结论；
- 阈值和计算时间。

索引用于来源判定和分析，不直接增加正式得分。

## 5. 系统自动记录的数据

以下数据不需要人工逐条添加，但必须持久化和审计：

- 战局配置快照；
- Agent 和 Arbiter 事件日志；
- Payload 草稿、冻结快照和哈希；
- `submissionId`、`correlationId` 和证据 ID；
- 每层检测状态和 `skipped-by-block` 记录；
- 响应起止时间与可信时钟来源；
- 每回合各评分项和计算证据；
- 安全对照执行结果；
- 相似度、来源标签和特征库动作；
- 整局汇总、统计指标和 Markdown 战报；
- 规则、特征、记忆的新增、审核、撤销和清空记录。

## 6. 跨局记忆规则

- 跨局记忆开启时，Attacker 和 Defender 同时开启；
- Attacker 读取自己的已审核策略记忆；
- Defender 读取自己的已审核特征，不读取未审核候选；
- 关闭开关时，新战局不读取历史记忆，但后台记录仍保留；
- 只要后台曾保存过记忆，即使当前关闭开关，也允许用户执行清空；
- 清空操作同时删除 Attacker 和 Defender 的跨局记忆，并保留操作审计；
- 清空后模型回到初始实验状态，但历史战报不应被连带删除。

## 7. 访问隔离

| 角色 | 可以读取 | 禁止读取 |
|---|---|---|
| Attacker | 样本库、授权范围、公开裁决、自身策略记忆 | Defender 黑名单、正式特征、安全对照、隐藏真值 |
| Defender | 当前 Payload、防御规则、工具权限、已审核特征 | Attacker 私有策略、隐藏真值、安全对照标签 |
| Arbiter | 全部事件、隐藏真值、安全对照、评分规则 | 不适用，但所有访问必须审计 |
| 管理员/审核员 | 候选规则、证据、版本和审核队列 | 不得绕过审计直接修改已结算战局 |

数据库、缓存、API 和日志均应执行相同访问隔离，不能只依靠前端隐藏。

## 9. 验收原则

- 任一正式评分都能追溯到规则版本和证据 ID；
- Attacker 无法读取 Defender 私有规则和 Arbiter 隐藏数据；
- Defender 学习产生的特征未经审核不会自动进入正式规则库；
- 每个有效攻击回合均有独立安全对照；
- 错误结果不能通过响应速度补分；
- 关闭跨局记忆后新战局不读取旧记忆，但用户仍可主动清空后台记忆；
- 规则更新不追溯修改已经结算的历史战局；
- 所有新增、审核、发布、撤销和清空动作都有审计记录。
