# 需求分析取证包（5 位使用者）

用途：补上评分细则「需求分析 10 分」最缺的一项——**外部使用者证据**。
现状问题：需求条目（R1–R5）是从产品功能反推的，没有真实使用记录，材料里写不出"谁需要、为什么需要"。
本包目标：用 **30 分钟/人** 的成本，产出 5 份可引用、可核验的使用记录。

使用前提：**只记录真实发生的事**。不接受"我大概会用""应该有用"这类口头评价，每个结论背后要有一张截图或一条原话。

---

## 一、怎么用（执行清单）

| 步骤 | 谁做 | 产出 |
|---|---|---|
| 1 | 你 | 找 5 个人：2 个开发/测试同事、1 个安全方向、1 个产品/运营、1 个非技术（覆盖不同视角） |
| 2 | 你 | 把「第三节 纯文本问卷」直接微信发给对方，先收 6 题回答（约 5 分钟） |
| 3 | 你 | 约 15 分钟，让对方**自己操作**跑一局（你在旁边只观察不指导），按第四节截图 |
| 4 | 你 | 把回答 + 截图填进「第六节 汇总表」，每人一条 |
| 5 | 我 | 根据汇总表改材料里的「需求分析」章节 |

时间预算：5 人 × 30 分钟 ≈ 2.5 小时，可并行。

---

## 二、问什么、为什么问（设计说明）

| 题号 | 问什么 | 对应需求条目 | 拿到的证据 |
|---|---|---|---|
| Q1 | 背景与既有做法 | R1 | 证明"这个场景真实存在"，不是我们编的 |
| Q2 | 现在怎么解决、卡在哪 | R1 | 痛点原话，可直接引用 |
| Q3 | 最有用的是哪个输出 | R2 / R3 | 证明防守证据与样本的价值排序 |
| Q4 | 能不能判断结果可信 | R3 / R4 | 证明"来源字段 + 证据"是刚需，不是炫技 |
| Q5 | 会不会用在真实系统、顾虑是什么 | 边界 | 证明我们"不碰真实目标"的设计是被理解的，不是遮掩 |
| Q6 | 复用意愿 + 一个必改点 | 改进方向 | 总结与展望的素材 |

---

## 三、纯文本问卷（可直接复制转发）

```
帮我做个 5 分钟的可用性反馈，关于我们做的「智能体攻防实验室」——
它跑一局会输出：攻击测试样本、防守的命中证据与修复建议、独立裁决、带调用追溯的战报。
你随便说真实想法就行，不用夸。

1）你的工作角色大概是？（开发/测试/安全/产品运营/其他）
2）在接触这个之前，如果要做「提示词注入/越狱」这类 AI 安全自查，你会怎么做？最烦的是哪一步？
3）跑完一局，下面四项里对你最有用的是哪个？请排个序：
   A 攻击样本  B 防守命中证据与风险等级  C 独立裁决结论  D 带调用追溯的战报
4）你能不能从输出里判断"这条结论靠不靠谱"？哪一块你看不懂或不敢信？
5）你会把它用在真实系统上吗？如果不会，主要顾虑是什么？
6）1–5 分，你愿意在下次迭代继续用/推荐给同事吗？给一个你觉得必须改的点。
```

> 记录要求：Q2、Q4、Q5 尽量留**原话**（截图或复制文字），材料里引用原话比转述有力。

## 四、15 分钟实操脚本（让对方自己点，你只观察）

固定参数，保证 5 个人的体验可比：

| 项 | 值 |
|---|---|
| 地址 | `https://yuanyiagentzhandui.cn` |
| 主题 | 客服机器人泄露内部系统提示词 |
| 难度 | 高（high） |
| 轮数 | 3 轮 |

观察点（你记录，不要提示对方）：

1. 从打开页面到点"开始"，用了多久、卡在哪；
2. 战局进行中，对方先看哪块内容；
3. 看到裁决结论时，第一句话说什么；
4. 有没有去点"事件 / correlationId"这类追溯信息（**大多数不会点，这本身是结论**）。

必截 4 张图（每张都要含地址栏与时间）：

| # | 截图内容 | 证明什么 |
|---|---|---|
| 1 | 发起页（主题、难度、轮数已填） | 操作可复现 |
| 2 | 战局进行中 | 流程真实跑通 |
| 3 | 裁决结果（含"真实目标未验证"限定） | 结论带边界 |
| 4 | 战报里的来源字段（`agentSource`） | 可追溯到具体通路 |

脱敏：截图里不要出现密钥、Token、他人姓名；文件名用 `需求证据-01-角色.png`，不写真实姓名。

## 五、材料里怎么写（引用模板）

每条结论 = **一句判断 + 一条证据（n=5）**，不写"用户普遍认为"这种无主语的话。

```
需求侧证据（n=5，2026-10-28 实测，参与者角色：开发 2 / 安全 1 / 产品 1 / 非技术 1）：
1. 5 人中有 4 人在接触本系统前用"手工构造提示词 + 人工看回复"做自查，其中 3 人提到
   "无法判断是否真的越狱成功"（原话见附录 A-2、A-4、A-5）→ 对应 R1、R2。
2. 四项输出排序中，防守命中证据被 5 人中的 4 人排在前两位；裁决结论仅 1 人排第一
   → 说明"证据型防守"比"胜负判定"更贴近真实需求，对应 R3。
3. 5 人均表示不会直接对生产系统使用，主要顾虑为"样本可能误伤真实业务"（原话见 A-1、A-3）
   → 与本系统"不访问真实目标、只给修复建议"的边界设计一致。
```

**不能写**：
- "用户满意度 90%"（样本 5 人，不构成比例结论）；
- "多家企业反馈"（无企业用户）；
- 把 2 个人的意见写成"用户普遍认为"。

| 4 | | | | | | | □ |

填完后可直接回答三个问题，也就是材料里要写的三句话：

1. **谁在用**：5 人的角色分布；
2. **替代方案是什么、差在哪**：Q2 归纳出的 1–2 个共性痛点；
3. **哪些功能被真正需要**：Q3 排序 + Q4 的"看不懂/不敢信"点。

## 七、常见坑

| 坑 | 处理 |
|---|---|
| 让对方"评价一下这个系统" | 会得到客套话。必须问"你原来怎么做"，问行为不问评价 |
| 你在旁边指导操作 | 观察结论作废。只回答"页面在哪"，不解释功能 |
| 只收口头意见不留原话 | 材料引用不了。Q2/Q4/Q5 必须截文字或复制原话 |
| 5 个人全是同岗位 | 视角单一，评委会问"非技术用户怎么用"。至少 1 个非技术 |
| 截图带密钥/他人信息 | 一律重截或打码，不要带进材料 |

- 链接是公开的，任何人可填。回收后先按 IP/时间筛一遍，明显是机器人的（同一秒多条、字段全填"其他"）剔掉再进材料。
