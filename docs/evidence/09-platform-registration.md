## 二、第 7 项：平台调用排行

平台首页左侧「梧桐智能体调用排行榜」，统计窗口 **2026-10-21 22:00 — 2026-10-28 22:00（最近 7 天）**，
单位 task。截图 `20-platform-rankings.png`。

同窗口的接口原始数据（`raw/platform-rankings-20261028.json`）：

| 项 | 数值 |
|---|---|
| 被调用方（callee）条目 | 159 |
| 调用方（caller）条目 | 73 |
| 榜首被调用量 | 33,839 task |
| 我方 AIC 前缀 `1.2.156.3088.1.BUPT.RX2TMW` 命中 | **0 条（caller 与 callee 都没有）** |

结论：**平台侧对本站的调用量为 0**，所以排行榜上没有我们。这不是"调用少"，是**一次都没有成功**。

原因已单独定位并留证（`PLATFORM_ACCESS_DATA_20261028.md`）：

- 我们发往平台的 `/rpc` 请求两周内 418 次，VPS nginx 日志可查，全部来自本项目；
- 平台经 `acps-sdk` 的 `MTLSConfig` 按固定路径 `{aic}.crt/.key` 加载证书，缺文件即抛错，
  平台侧报 `mTLS connection failed`，调用在建立连接阶段就失败；
- 证书路径与命名由平台 SDK 约定，**我方无法修改**。

## 三、使用方法（材料里怎么写）

- 第 3 项可以直接引用 17/18/19 三张图：**注册已通过 + 能力声明 + 审核意见**都在同一账号下可查。
- 第 7 项只能如实呈现"0"：截图证明榜单与统计窗口，接口数据证明我方 AIC 零命中，
  再加平台侧的报错结论。**不要**把"榜单上没有我们"包装成"排名靠后"。
- 如果平台后续修复证书加载，这段证据需要重采；重采口径：同一账号、同一 7 天窗口、同一接口参数
  （`startAt`/`endAt` 使用 `YYYY-MM-DDTHH:00:00+08:00` 格式，`n=200`）。
